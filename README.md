# 桔梗が丘 電子区域地図

Leaflet と地理院地図を使う静的アプリです。クエリなし／`?t=home` は個人のホーム、`?t=4` は区域4、`?t=all` は全体図です。S-12などの区域指定QRは引き続き直接その地図を開きます。

## 個人のホームと使った地図

- 地図のヘッダーにある家のアイコンからホームへ戻れます。「使った地図」「再訪問」「奉仕時間」を全区域まとめて表示します。奉仕中にホームへ移動してもタイマーは続き、元の区域へ戻るリンクを表示します。
- `personal.js` は、開いた登録済み区域を `map-history` に `{terr, name, lastOpened}` の配列として保存します。同じ区域は1件にまとめ、最終表示が新しい順で表示。全体図・ホーム・未登録区域は追加しません。貸出や返却の管理記録ではありません。
- 「履歴を編集」から区域ごとの削除と全削除ができます。削除した区域番号は `map-history-hidden` に保存し、訪問記録が残っていても履歴へ自動復元しません。その地図をもう一度開くと非表示を解除して履歴に戻します。再訪問・訪問記録・奉仕時間は削除しません。
- 以前の戸建て・建物／部屋・奉仕時間に残っている区域も追加します。開いた日付は推測せず `lastOpened: null` とし、「以前の記録から追加」と表示。新機能以前に開いただけで保存データのない区域は復元できません。
- ホームの再訪問は全区域の家と部屋をIDで集約。共有建物の名前と位置は既存の公開CSVから取得し、未取得・削除済みの建物や部屋の個人記録も残します。再訪問のリンクはURLのフラグメントにIDだけを持ち、該当する家・部屋を開きます。
- 「バックアップ・記録の整理」内の「この区域の記録を整理」は、件数確認後に「会えた・投函・留守」の戸建てピンとメモを削除し、部屋の状態・日付を空にします。再訪問・訪問しない・未選択の戸建て・建物と部屋番号・共有情報・奉仕時間・地図の使用履歴は保持します。
- 整理は3種類の区域保存キーを一括で処理します。検証エラー・確認中の他タブ変更・書き込みエラー時は整理を中断。直後15秒の「↩」では全部をまとめて復元します。
- 訪問先の過去の状態を日付ごとに蓄積する機能は追加していません。使用中の最新状態と、整理後も残す再訪問を扱います。端末外への個人記録の送信はありません。

## 今回の改善

- 記録画面を「今日の振り返り → 再訪問・留守の確認 → 家・部屋の一覧」に整理。バックアップや削除は折りたたみ内に配置。
- 今日の件数は、この区域・この端末に残る家／部屋ごとの最新状態のうち、日付が今日の「会えた・再訪問・投函・留守」。訪問しない・未選択は含めず、訪問回数・累計・区域全体の達成率とは扱わない。
- 新しい訪問状態の日付は端末のローカル日付で `YYYY-MM-DD` を保存。年のない旧記録は推測せず、一覧に保持して今日の集計から除外。家の追加だけでは「会えた」を付けず、状態を選んで記録する。
- `records.js` は表示用の集約処理。家と部屋をまとめて検索・絞り込みできる。共有済みの建物はIDで重複を除き、建物情報が取得できない記録や削除済みの部屋の記録も消さずに表示する。訪問記録の外部送信はない。
- 伝道終了時は今回の時間と、この区域の今日の内訳を表示。数字の順位・連続日数・ノルマは設けない。
- アパートの部屋表示で参照できなかった状態定義を修正。
- 「記録」から家・建物・注意のどれか一つを選択。同じボタン、または記録メニューを閉じると記録モードを終了。
- 凡例を開閉式にし、部屋の状態ボタンを押しやすく調整。
- 共有情報の取得結果・最終取得時刻・再取得ボタンを表示。取得失敗を「空き」「注意事項なし」と扱わない。再取得失敗時は、この画面で前回取得した表示を保持。
- コピーの成功を確認し、失敗時は手動コピー用の欄を表示。
- 記録変更の直後15秒は地図の＋／−の下に出る「↩」で直前の保存に戻せる。連続した文字入力はまとめて取り消す。奉仕タイマーは取り消しの対象外。
- 全区域の家・端末内の建物・共有建物の部屋別訪問記録・奉仕時間・使った地図をまとめてJSONバックアップ。既存の区域別JSON書き出し・読み込みも維持。

## 建物・部屋番号の共有

既存の注意事項用スプレッドシート内に `apartments_shared` タブを追加しています（gid `2125994133`）。元の注意事項タブ（gid `0`）は保持しています。

列順は以下のとおりです。

| A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- |
| 区域番号 | 建物ID | 緯度 | 経度 | 建物名 | 部屋番号 |

1行が1棟です。部屋番号は `101,102,201` のようにカンマ区切りで入力します。建物IDは半角英数字・ハイフン・アンダースコアで、同じ区域内で一意にします。建物の名前・部屋番号を変更してもIDは変えません。建物名は任意です。氏名・訪問結果・個人メモは入れません。

アプリの建物画面で「建物・部屋番号を共有用にコピー」を押し、担当者がこのタブのA列から貼り付けます。変更は同じIDの行を更新し、重複行を作らないでください。部屋番号の列は文字列形式です。タブにはテストの建物データを入れていません。

共有先で `local-` で始まる建物IDを維持すると、作成元の端末の部屋別訪問記録を引き継ぎ、同じ建物を重複表示しません。他の端末には訪問記録は送られません。

共有データの建物情報は担当者がシートで編集します。アプリ内では共有建物の名前・部屋番号を編集できず、訪問記録だけを端末内に保存します。共有シートで削除された部屋の訪問記録は、端末から自動削除しません。

新しいタブの公開CSVは既存の公開用URLにgidを指定して参照します。既存の公開設定によって、新しいタブが公開対象に含まれていない場合があります。アプリに取得失敗が出る場合は、管理者がGoogle Sheetsの「ウェブに公開」で対象タブと公開範囲を確認してください。この変更では公開権限を変更していません。

## 保存・復元

訪問記録はlocalStorageです。ブラウザーのデータ削除、別端末への移行、異なるドメインへの移動では引き継がれません。「訪問記録」→「バックアップ・記録の整理」→「全記録をバックアップ」でダウンロード先にファイルが保存されたことを確認してください。

復元はファイルに含まれるキーだけを置き換え、ファイルにない区域は残します。復元前に現在の全記録をバックアップしてください。不正な形式を検出した場合は書き込まず、容量不足時は既存値へ戻します。共有建物の訪問記録には全記録バックアップを使用してください。「端末内の建物を書き出し」は従来どおり端末内の建物のみです。

## 検証

```
npm ci
npm test
```

本番アプリにはnpmやビルド処理は不要です。開発用のlinkedomはDOMテストだけに使用します。Leafletはテストで模擬しています。テストは実ブラウザーでの画面配置・地図通信・クリップボード権限・Googleの公開CSV設定の確認を代替しません。
